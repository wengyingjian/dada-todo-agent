# 端到端验收（对应需求规格 §10）

用例直接驱动真实的 Obsidian：通过 Chromium 调试协议在渲染进程里点按钮、读文件、看界面，
不 mock 插件、不碰数据库，会真的起 T3 Code 会话（可用 `--skip-slow` 跳过）。

## 前提

1. 插件已构建并安装：`node scripts/install.mjs ~/Documents/ObsidianVault`
2. Obsidian 以调试端口启动（先退出，再执行）：

```bash
/Applications/Obsidian.app/Contents/MacOS/Obsidian --remote-debugging-port=9333
```

> 9222 常被其它 Electron 应用（如 WorkBuddy）占用，默认用 9333。

## 运行

```bash
node scripts/e2e/run.mjs                 # 全部
node scripts/e2e/run.mjs --skip-slow     # 跳过要真起 T3 Code 会话的 8/9/12/13
node scripts/e2e/run.mjs --only 1,5,7    # 只跑指定编号
```

测试数据分两处，跑完都会清掉，并还原插件设置；不会碰 `任务/`、真实日记和你的其它 T3 项目：

- 库内 `__e2e/`：测试用的项目文件与日记；
- 库外沙盒 `~/Documents/ObsidianWork/e2e-dada-todo`（可用 `E2E_SANDBOX` 改）：所有真实 AI 会话都在这里跑。
  脚本会在开跑前把它登记成一个独立的 T3 项目，跑完 `t3 project remove --force` 删掉，
  连同测试会话一起消失——不会留在你的正常项目里。

> 新建的 T3 项目没有默认模型，所以脚本会从库项目最近的会话里读出「提供方 + 模型」，
> 既写进插件的「委派模型」设置（面板委派用），也作为命令行参数（外部会话用）。

## 跑崩了 / Ctrl-C 了怎么办

脚本会在退出时自动还原设置（含中断与未捕获异常）。万一还是留下了测试值，手工改回来：

- 插件设置「项目与委派」：项目根目录改回 `任务`
- 日记文件夹改回 `10-时间轴/日记`
- 删除库根 `__e2e/` 目录
- 忽略会话列表里可以清掉那批测试会话 id（不清也不会回灌到日记）
